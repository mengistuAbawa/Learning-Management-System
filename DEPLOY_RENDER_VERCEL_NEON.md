# Render, Vercel, and Neon deployment

This repository is configured for a Vercel-hosted Vite frontend, a Render-hosted
Express API, and a Neon PostgreSQL database. Deploy the API and database first;
the Vercel frontend needs the Render API URL at build time.

## 1. Create and initialize Neon

1. Create a Neon project and database. Keep the pooled connection string private.
2. From the repository root, create a local `server\.env` from
   `server\.env.example` and set `DATABASE_URL` to the Neon connection string.
   The database client uses TLS with certificate verification for URL-based
   connections.
3. Initialize a **new, empty** Neon database with `database\schema.sql`, then
   apply the following SQL files exactly once in order. Run these commands
   from Windows CMD. The Node script loads `server\.env` and connects using
   `DATABASE_URL`:

   ```cmd
   cd /d D:\xampp\htdocs\LearnSphere-LMS\server
   node scripts\apply-migration.js ..\database\schema.sql
   node scripts\apply-migration.js sql\step12_assessments.sql
   node scripts\apply-migration.js sql\step13_notifications.sql
   node scripts\apply-migration.js sql\step14_admin_platform.sql
   node scripts\apply-migration.js ..\database\migrations\20261023_enrollment_timestamps.sql
   node scripts\apply-migration.js ..\database\migrations\20261024_analytics_schema_corrections.sql
   node scripts\apply-migration.js ..\database\migrations\20261024_course_videos.sql
   node scripts\apply-migration.js ..\database\migrations\20261024_course_video_status.sql
   node scripts\apply-migration.js ..\database\migrations\20261025_advanced_quiz_attempts.sql
   node scripts\apply-migration.js ..\database\migrations\20261025_assignment_schema_alignment.sql
   node scripts\apply-migration.js ..\database\migrations\20261025_course_categories.sql
   node scripts\apply-migration.js ..\database\migrations\20261025_course_video_metadata.sql
   node scripts\apply-migration.js ..\database\migrations\20261025_course_video_progress.sql
   node scripts\apply-migration.js ..\database\migrations\20261025_admin_console.sql
   node scripts\apply-migration.js ..\database\migrations\20261025_quiz_manual_grading.sql
   node scripts\apply-migration.js ..\database\migrations\20261025_student_approval.sql
   node scripts\migrate-live-classes.js
   ```

   The project does not currently maintain a migration ledger or automatically
   apply every migration. Do not run `schema.sql` against an existing database,
   and take a Neon backup before applying schema changes to a database with
   data. Track which migrations have been applied.

## 2. Deploy the API to Render

1. In Render, create a Blueprint deployment from the repository and select
   `render.yaml` at the repository root.
2. The blueprint configures the API service from `server`, runs `npm ci` and
   `npm start`, checks `/api/health`, and mounts a 10 GB persistent disk at the
   application's `server/storage` directory for uploaded course videos.
   **Render's `starter` service plan and persistent disk are paid resources.**
   Review current Render pricing before deploying.
3. When prompted, set:
   - `DATABASE_URL`: Neon's pooled connection string. Keep it server-side.
   - `CLIENT_URL` is set by the Blueprint to
     `https://learning-management-system-mu-eight.vercel.app`. It must be the
     exact frontend origin (scheme and host only). Update the Blueprint if you
     change the Vercel project or use a custom frontend domain.
   - `JWT_SECRET` is generated by the blueprint. Keep it private and do not
     regenerate it after launch unless you intend to invalidate active tokens.
4. Verify `https://<render-service>.onrender.com/api/health` returns HTTP 200
   and reports `database: "connected"`.

To enable LiveKit classrooms, add `LIVEKIT_URL` (`wss://`), `LIVEKIT_API_KEY`,
and `LIVEKIT_API_SECRET` to the Render service environment. Never add the API
secret to Vercel or any `VITE_*` variable.

## 3. Deploy the frontend to Vercel

1. Import the repository into Vercel.
2. Set the project **Root Directory** to `client`. `client/vercel.json` supplies
   the Vite build command, `dist` output, and SPA fallback for React Router.
3. Set the Vercel environment variable `VITE_API_URL` in every environment
   you deploy:

   ```text
   https://<render-service>.onrender.com
   ```

   The frontend automatically appends `/api`, so either the origin above or
   the origin ending in `/api` is accepted. Vite embeds this value during
   build; redeploy after changing it.
   Vercel production builds now fail with a configuration error if this value
   is missing, not HTTPS, points to localhost, or has an unsupported path.
4. If the Render service already exists, sync the Blueprint change or set the
   Render service's `CLIENT_URL` to
   `https://learning-management-system-mu-eight.vercel.app` (do not include
   `/login` or another path), then redeploy/restart the API service. The API
   must return `Access-Control-Allow-Origin` with that exact origin for
   browser requests to work.
5. Test sign-in and `https://<render-service>.onrender.com/api/health` from the
   deployed frontend origin.

## Production notes

- Render serves the API over HTTPS; Vercel serves the frontend over HTTPS.
  LiveKit requires an HTTPS browser origin and a secure `wss://` LiveKit URL.
- Uploaded course videos are stored on the Render persistent disk, not Neon.
  The disk is attached to one Render service instance; maintain backups and do
  not scale the API horizontally without moving uploads to shared object
  storage.
- Keep production secrets only in Render's environment settings. Do not commit
  `.env` files or put database credentials, JWT secrets, or LiveKit secrets in
  Vercel client variables.
- `CLIENT_URL` accepts one production origin. If using Vercel preview
  deployments, add the intended preview origin through a deliberate CORS
  policy change rather than a wildcard.
- Run migrations manually before deploying backend code that depends on them;
  automatic production migrations are intentionally not enabled.
- Real-time media requires a configured LiveKit provider. The app reports
  missing LiveKit configuration rather than presenting a simulated classroom.
